# ADR-0002: 실험의 단위를 A/B 쌍에서 사전 등록된 함대로 확장한다

> **상태:** Accepted
> **날짜:** 2026-07-16

## Context

LLM이 변형 생성 비용을 0에 수렴시키면서 실험의 병목이 생성에서 트래픽과 판정으로 이동했다. 업계는 이미 실험의 단위를 바꾸고 있다 — Yum!/KFC는 Braze AI Decisioning으로 연 2억 건 이상의 상호작용을 AI가 결정하게 했고, Booking.com은 상시 1,000개 이상의 동시 실험을 운영하며, Statsig·Amplitude·Optimizely는 실험 생성·배분 자동화를 제품화했다([research](../../features/experiment-fleet/research.md)).

같은 조사에서 두 가지가 함께 확인됐다. 첫째, 보정 없는 대량 실험은 오탐을 양산한다(다중 비교, 승자의 저주, novelty effect). 둘째, 상용 도구들은 밴딧 확률 배분이나 AI 판정으로 이동하면서 **결정적이고 감사 가능한 판정**이라는 영역을 비워 두고 있다 — 이는 본 제품의 기존 차별점이다.

## Decision

실험 단계에 선택적 확장으로 "experiment fleet"를 도입한다.

- 함대는 **정책 사전 등록**으로 시작한다: threshold·변형별 최소 표본·표본 예산·동시 상한·생존 비율·guardrail·종료 규칙.
- 웨이브 판정은 **결정적 successive halving**이다: guardrail 위반 컷 → 표본 부족 재수집 → 원시 delta 순위 → keepShare 컷. 변형별 수치는 기존 `evaluateExperiment`를 그대로 재사용한다.
- AI의 역할은 변형 후보 제안까지다. 승격 후보 산출은 코드가, 최종 결정은 사람이 Decision으로 기록한다.
- 사람의 역할 이동을 제품 구조로 만든다: 변형 선택자가 아니라 정책 설계자·최종 결정권자.

## Alternatives

### 밴딧 자동 배분 (Thompson Sampling 등)

업계 표준이지만 확률적 배분은 재현·감사가 어렵고 "코드가 결정하고 사람이 기록한다"는 본 제품 원칙과 충돌한다. 채택하지 않는다.

### 통계적 유의성 엔진 (FDR 보정 포함)

대량 실험의 정석 완화책이지만, 본 제품은 소규모 트래픽 사용자를 전제로 p-value 자동 판정을 이미 배제했다(A-002~A-004). practical threshold 체계를 유지하고, 다중 비교 한계는 수치가 아니라 명시적 문구로 병기한다.

### 아무것도 하지 않기

실험 단위의 대량화는 독립적으로 검증된 방향이다. 단일 A/B 쌍만 지원하면 AI가 후보를 대량 생성하는 워크플로를 담을 수 없다.
